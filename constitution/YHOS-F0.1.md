# YHOS-F0.1｜Sovereign Founder Dual-System Health OS Constitution

## 0. 宪法定位

本文件是 `yuanli-life/yuanli-health` 面向企业家 Principal 的**公共产品与能力调用宪法候选**。

它不是新的 Health Domain Constitution，不重写上游 `yuanli-strategy-soul`，不创建第二套 Health truth，不创建新的临床法权，不保存真实个人健康数据，也不复制 `yuanli-health-skills` 的原子能力实现。

本宪法只回答一个问题：

> **企业家如何以最低认知负担，安全、专业、可追溯地调用完整的 Performance × Healthspan 双系统健康能力，并让真实结果持续形成可复用的个人健康学习？**

在 Human Review 与受治理合并完成前，本文件保持 `proposed`，不得宣称已冻结、已激活或已成为上位法。

---

## 1. North Star｜Health Optionality

> **在医学安全与本人主权边界内，持续扩大企业家 Principal 的长期生命选择权。**

用户语言：

> **让身体有余量，让人生有余地。**

Health Optionality 不是健康总分，不是寿命预测，不是 Performance 分数，也不替代具体临床 Outcome。

---

## 2. 母架构｜One Kernel × Two Engines × One Learning System

```text
                         HEALTH OPTIONALITY
                         长期生命选择权
                                ▲
                                │
              ┌─────────────────┴─────────────────┐
              │                                   │
     PERFORMANCE ENGINE                  HEALTHSPAN ENGINE
     Deployable Capacity               Sustainable Healthspan
        今日可调用能力                     长期生命底盘
              │                                   │
   6 Human Functional Capacities     Longitudinal Completeness Scan
              │                                   │
              └─────────────────┬─────────────────┘
                                │
                         SHARED HEALTH KERNEL
       Principal / Purpose / Evidence / Context / Clock /
       Authority / Longitudinal Memory / 12 Health Domains
                                │
                     ONE REALITY LEARNING SYSTEM
        CTX → EVD → DEC → WPK → ACT → OUT → LRN → REUSED
```

### 2.1 One Kernel

双系统共享同一个 Principal、同一 Evidence 链、同一纵向记忆、同一 Authority、同一 Health Clock 纪律、同一 12 Health Domains Scientific Backbone 与同一现实学习链。

**Two Engines, One Truth.**

两个 Engine 是同一 Kernel 上的两种受治理判断与调用模式，不是两颗 Kernel、两套 Canon、两套健康真相或两套个人档案。

任何 Surface、Agent、Skill、Performance 判断或 Healthspan 判断都不得建立第二套关于同一 Principal 的正式健康真相。

### 2.2 Performance Engine

Performance Engine 负责短周期的 **Deployable Capacity｜今日可调用能力**，主要回答：

> 今天与眼前重要人生情境中，这个人还能安全调用多少身体、认知、恢复、应变与心理能力？

其六大**生命功能能力｜Human Functional Capacities**：

- `Recover`｜恢复
- `Adapt`｜应变
- `Energize`｜供能
- `Move`｜身体储备
- `Think`｜认知表现
- `Connect`｜心理与意义

这六项是 Functional Projection，不是第二套 Health Ontology，不是六个医学领域，也不是六条独立产品线。

**命名硬规则：不得把它们泛称为“FHP2 六项能力”。** FHP2 Strategic Charter v2 已经使用另一组“六项产品运行能力”：Evidence Vault、Truth Compiler、Battle Engine、Intent Gateway、Outcome Ledger、Settlement Engine。二者法权身份完全不同。

Performance Engine 可按 Intent / Context / Evidence 路由进入共享 12 Health Domains；它不拥有独立科学本体。

### 2.3 Healthspan Engine

Healthspan Engine 负责 **Sustainable Healthspan｜长期生命底盘**，主要回答：

> 哪些身体结构、疾病风险、功能储备、筛查债务与未闭环问题，正在影响未来十年、二十年的重要人生选择？

FHP2 的 12 Health Domains 是**Shared Scientific Completeness Backbone｜共享科学完整性骨架**，两个 Engine 都可调用。

Healthspan Engine 的特殊责任不是“拥有 12 Domains”，而是：

- 对 12 Domains 进行长期 completeness scan；
- 发现 silent risk、screening debt、follow-up debt 与 unresolved risk；
- 在 Clinical / Longitudinal Clock 下维护长期风险与能力底盘；
- 将与当前能力相关的长期结论投影回 Performance。

12 Domains 不是用户入口，不要求同步建设十二条产品线。

### 2.4 One Learning System

双系统共享唯一现实脊柱：

```text
CTX → EVD → DEC → WPK → ACT → OUT → LRN → REUSED
```

硬边界：

- `ACT ≠ OUT`
- `OUT ≠ Attribution`
- `OUT ≠ LRN`
- `LRN approved ≠ REUSED`
- 没有第二真实任务的**事前 preload + 实际使用 + reuse receipt**，不得宣称复利。

## 3. 双系统关系｜不是并排，而是互相约束与建设

### 3.1 Performance under Healthspan Guardrails

Performance 优化永远不能越过医学安全、不可逆长期风险与临床法权。

```text
Safety
→ Irreversible Long-term Risk
→ Important Life Context
→ Deployable Capacity
→ General Optimization
```

当短期表现目标与长期安全冲突时，长期安全优先。

### 3.2 Healthspan built partly through Capacity

长期 Healthspan 并不只靠筛查与临床闭环；Recover / Adapt / Energize / Move / Think / Connect 的长期建设可以成为 Healthspan 的能力底盘，但任何短期能力改善都不得自动升级为长期临床风险改善。

### 3.3 Cross-System Learning

Performance 的真实 Outcome 可以形成未来 Healthspan 决策可用的 Learning；Healthspan 的临床/长期 Learning 也可以改变未来 Performance 决策。

跨系统复用必须留下可追溯 `reuse receipt`，不得以“两个系统都引用过同一条数据”冒充复用。

## 4. Founder Intent｜调用入口，不是健康本体

企业家不需要理解系统结构；自然语言是第一入口。

一级 Intent Vocabulary 冻结为五类：

1. `today_capacity`｜今日余量
2. `key_moment`｜关键时刻
3. `body_signal`｜身体提醒
4. `life_disruption`｜现实扰动
5. `long_game`｜长期余地

Intent 的法权身份：**Invocation Layer only**。

它只能路由现有 Kernel，不得创建新的 Domain、Truth、Clinical Authority 或 Canon。

默认路由：

- 今日余量 → Performance-first + Healthspan safety guardrail
- 关键时刻 → Performance-first + Healthspan safety guardrail
- 身体提醒 → Healthspan-first + Performance impact projection
- 现实扰动 → Coupled
- 长期余地 → Healthspan-first + Capacity-building projection

## 5. Shared Kernel 六个正交平面

### P1 Purpose
回答：本人最终想保护什么？

最低对象：Principal purpose / priorities / constraints / sovereignty boundary。

### P2 Intent
回答：本人此刻真正想解决什么？

只用于调用和路由。

### P3 Human Functional Capacity
回答：人的哪种可调用生命功能能力受到影响？

使用 Recover / Adapt / Energize / Move / Think / Connect。

### P4 Domain
回答：专业上涉及哪些健康问题？

使用上游 H01–H12 共享 Health Domains，承担科学完整性与专业解释；两个 Engine 都可调用。

### P5 Context × Clock
回答：在什么现实情境与时间尺度下判断？

- Founder Context 负责现实调制；
- Health Clock 负责时间尺度纪律；
- 短周期信号不得静默覆盖长周期结论。

### P6 Evidence × Authority
回答：凭什么知道？谁有资格决定？

必须显式区分 Evidence provenance、Scientific truth、Personal truth、Clinical truth 与相应 Authority。

## 6. Health Clock

公共调用层至少支持：

- `now`｜即时
- `daily`｜日
- `weekly`｜周
- `experimental`｜干预窗口
- `clinical`｜临床
- `longitudinal`｜长期

上位硬规则：

> **Short clock cannot overwrite long clock.**

例如短期 HRV、体重或主观状态改善，不得自动宣称长期心血管、肿瘤、器官风险改善。

---

## 7. Evidence 与 Truth Discipline

系统必须保持：

```text
Signal
≠ Observation
≠ Fact
≠ Interpretation
≠ Decision
≠ Action
≠ Outcome
≠ Attribution
≠ Learning
```

任何缺失、冲突、过期、不可比、不知道，必须被保留，不得由 AI 静默补齐。

AI 可以整理、检索、归纳、提出候选解释、比较证据与生成候选行动；不得把生成文本升级为临床事实、正式诊断、处方、停药或侵入性检查裁决。

---

## 8. Health Office｜复杂度吸收层，不是第二 Health Kernel

Health Office 位于 Shared Kernel 与用户 Surface 之间：

```text
Health Kernel
    ↓
Health Office
AI Health Brain + Health Steward + Expert Network
    ↓
Principal Surfaces
```

Health Office 的职责：

- Intent 编译
- Priority 编译
- Attention 路由
- Evidence 准备
- Expert / Clinical 编排
- Follow-up
- Ownership state
- Outcome 回收
- Learning 候选准备

Health Office 可以吸收管理复杂度，但不得吸收 Principal 最终选择权，也不得夺取 Clinical Authority。

## 13. 三重 Gold Gate

任何能力、Journey 或 Domain 投影进入 Gold，必须同时：

### Scientific PASS
证据有来源；纵向比较合法；未知显式；Clock 正确；Clinical boundary 不越界。

### Principal PASS
30 秒可理解；最重要优先；产生最少必要行动；降低管理负担；不过度打扰。

### Reality PASS
真实 ACT 可验证；OUT 被观察；LRN 可审查；若宣称复用，必须有 Task2 preload 与 reuse receipt。

```text
Gold = Scientific PASS × Principal PASS × Reality PASS
```

## 14. 七条不可变原则

### I1｜Health Optionality is the only North Star.

### I2｜Founder Intent is invocation, not ontology.

### I3｜Six Human Functional Capacities are functional projections, not Health Domains and not FHP2 runtime capabilities.

### I4｜Twelve Domains remain the shared scientific completeness backbone; neither Engine owns a separate Domain truth.

### I5｜Context and Clock modify judgment; they do not create truth.

### I6｜Evidence does not confer Authority; AI capability does not confer clinical authority.

### I7｜No verified Outcome → no Learning; no Task2 preload → no Reuse.

附加双系统硬规则：

> **Performance cannot override Healthspan safety.**
